# MultiPic — техническое задание

Версия: 1.0. Дата: 18 октября 2026 года.
Статус: спецификация для разработки. Компонент ещё не реализован; названия параметров API ниже — проектный контракт, который требуется подтвердить реализацией и тестами.

## 1. Назначение

Универсальный тип TV «MultiPic — галерея изображений» для массовой загрузки и управления фотографиями в MODX Revolution. Техническое имя пакета, пространства настроек и каталога — `multipic`. Сниппет — `MultiPic`.

Сценарии: фотогалереи, слайдеры, фотографии объектов, ход строительства с отдельными галереями по месяцам и корпусам. Компонент не зависит от miniShop2, MixedImage или MIGX при самостоятельном использовании.

## 2. Совместимость и границы

- Целевые ветки: MODX Revolution 2.8.x и 3.x; любые типы ресурсов.
- Обычное TV, несколько TV на ресурсе, поле обычного MIGX, вложенный MIGX.
- Подключение в MIGX через `inputTV` с именем созданного TV; наследуются параметры этого TV.
- MIGXdb не включён в подтверждённый объём первого выпуска: его транзакции и привязки требуют отдельного адаптера и проверки.
- До выпуска определить и опубликовать точные проверенные версии MODX, PHP и MIGX. PHP 7.4 — целевой сценарий для MODX 2; окружение MODX 3 проверяется отдельно. Поддержку не объявлять только по результатам статического анализа.
- Первый выпуск: локальный файловый медиаисточник MODX. Удалённые источники не считать поддержанными без отдельной реализации.

## 3. Настройки

### У конкретного TV

| Параметр | Поведение |
| --- | --- |
| Максимум файлов | По умолчанию 30; наследует общее значение, если не задан |
| Медиаисточник | Источник файлов для хранения и выбора с сервера; учитывает контекст MODX |
| Папка загрузки | Относительно источника; по умолчанию `multipic/`; можно указать `multipic/construction/`, `multipic/gallery/` |

Самостоятельное TV и его использование через inputTV имеют одинаковые параметры. Отдельного режима одиночного изображения нет: количество вывода ограничивается сниппетом.

### Общие настройки

- Значения по умолчанию для источника, папки и количества.
- JPG/JPEG, PNG, WebP.
- Максимум 2560 px по длинной стороне; без увеличения маленьких фото; возможность отключить уменьшение.
- Качество JPG/WebP: 95. Для PNG используется собственный параметр сжатия без потери прозрачности.
- Ограничение веса и числа пикселей: точные безопасные значения определить при проверке окружения; интерфейс показывает фактический предел с учётом PHP/сервера.
- Параллельная очередь: исходно 2 файла.
- Превью админки: небольшое, порядка 240 px для отображения карточки 110–120 px. Точный профиль утвердить при реализации.
- Очистка брошенных загрузок: 24 часа без активности; это технический срок, не корзина удалённых фотографий.

Изменение источника/папки влияет только на новые загрузки. Существующие URL не меняются. Массового переноса и переработки старых изображений в первом выпуске нет.

## 4. Интерфейс

Один редактор для TV, MIGX и вложенного MIGX. Стиль менеджера MODX, компактный, без дополнительных окон для управления галереей.

- Кнопки «Загрузить изображения» и «Выбрать на сервере», зона drag-and-drop, счётчик количества.
- На компьютере карточки около 110–120 px: ориентир 6–7 в ряд при соответствующей ширине, адаптивная сетка. 30 фото — примерно 5 строк.
- На телефоне один ряд с нативной горизонтальной прокруткой браузера, без карусели и стрелок. Сортировка только за маркер, не мешающий прокрутке.
- Карточка: превью, выбор, позиция, глазик, карандаш и удаление. Подсказки и доступные подписи у иконок.
- Выключенное фото тусклое, глазик перечёркнут. Первая включённая фотография — обложка.
- По карандашу внутри поля раскрываются необязательные «Название» и `ALT`, исходно пустые. Без ссылки и дополнительных метаданных для редактора.
- Просмотр фото по нажатию; если потребуется увеличенный слой просмотра, он не превращается в отдельный редактор.
- Сортировка перетаскиванием. Новые фото добавляются в конец. Внутри новой партии естественная сортировка исходных имён: `001`, `002`, `010`.
- Массовые команды при выделении: показать, скрыть, удалить.
- Прогресс/ошибка на конкретной карточке, «Повторить». Ошибка одного файла не останавливает остальные. Успех без всплывающего уведомления.
- Нет замены файла, архива скачивания, копирования/переноса между галереями, ручной обложки, crop, водяных знаков и редактора изображений.
- Ввод подписей и команды доступны с клавиатуры; ошибки не обозначаются только цветом.

## 5. Загрузка и обработка

1. Сформировать очередь и закрепить позиции карточек до отправки.
2. Сверить доступное число мест. При превышении загрузить первые подходящие файлы в доступные места, явно перечислить не вошедшие. Повторы и ошибки не занимают сохранённые места; после их выявления продолжить набор до лимита из выбранной партии.
3. Сервер проверяет авторизацию менеджера, право редактирования ресурса, доступ к TV и источнику. Сервер сам получает настройки TV, не доверяет переданным клиентом путям и лимитам.
4. Проверить размер, расширение, фактический MIME, декодирование и количество пикселей. Не принимать исполняемые файлы и произвольные URL.
5. Вычислить SHA-256 исходных байтов; найти результат для такого содержимого и профиля обработки в выбранном хранилище.
6. Новый файл: корректировать ориентацию EXIF, удалить GPS и ненужные метаданные, уменьшить при необходимости, сохранить прозрачность. Маленькие фото не пережимать без причины; удаление метаданных всё равно должно быть обеспечено безопасным способом.
7. Сохранить основной файл и превью, записать размеры, вес, MIME и хеши.
8. Добавить временную привязку к сессии редактирования; вернуть готовую карточку.

При отсутствии поддержки WebP сервером компонент показывает понятную причину, а не объявляет успешную загрузку. Анимированные PNG/WebP не должны молча терять кадры: в первом выпуске отклонять с объяснением, если анимация не поддержана.

Выбор с сервера: чтение только внутри разрешённого источника, собственная копия/обработка в папку MultiPic. Исходник не перемещать и не удалять. Существующий совпадающий файл MultiPic переиспользовать.

## 6. Имена и структура файлов

Папка TV — логическое хранилище. Внутри автоматически создаются распределённые подпапки, чтобы не хранить тысячи файлов в одном каталоге:

```text
multipic/construction/
  files/a7/f3/stroitelstvo-oktyabr-2026-a7f39c2e....jpg
  thumbs/a7/f3/stroitelstvo-oktyabr-2026-a7f39c2e....jpg
```

Имя: осмысленная часть + уникальный суффикс + проверенное расширение. Суффикс и атомарное создание предотвращают коллизии и перезапись; длину суффикса определить реализацией, короткий пример выше не является гарантией уникальности.

Осмысленное исходное имя транслитерируется и нормализуется. Для `001`, `IMG_1234` и аналогичных имён берётся название галереи/ресурса. Длина ограничивается. В MIGX необязательное сопоставление поля названия задаётся разработчиком; при его отсутствии используется название ресурса. Точное имя параметра интеграции подтвердить при проверке MIGX.

URL стабилен: переименование ресурса, подписи или изменение сортировки не переименовывает файл. Повторно используемый файл сохраняет первое имя.

## 7. Дедупликация и модель данных

Дедупликация ограничена одинаковыми медиаисточником и нормализованной папкой TV. Одинаковые байты в разных папках могут давать отдельные файлы: разделение по папкам сохраняется.

Хеш исходника + версия профиля обработки позволяют переиспользовать подходящий результат. Дополнительный хеш готовых байтов позволяет объединять точно совпавшие результаты. Визуально похожие или пересохранённые фотографии не обязаны считаться одинаковыми.

В одной галерее повтор файла пропускается с краткой отметкой. В разных галереях разрешён, без повторного хранения в той же папке. Гонки одновременных загрузок защищаются уникальными ограничениями БД/блокировкой и атомарной записью; счётчик ссылок без проверки источника истины недостаточен.

### Данные поля

Версионированный JSON с однозначной меткой MultiPic, идентификатором экземпляра галереи и упорядоченными элементами. У элемента: ID записи, ID файла, URL, ширина, высота, название, alt, active. URL и размеры доступны для прямого foreach. Служебные ID и пути проверяет сервер; клиентский JSON не является разрешением удалить файл.

Названия/alt/видимость/порядок принадлежат галерее. Файл и превью принадлежат общему реестру. При копировании ресурса или строки галерея получает независимую идентичность; файлы остаются общими. Не использовать только индекс строки MIGX как постоянный идентификатор.

### Служебные таблицы

- Реестр файлов: источник, папка, пути, URL, MIME, размеры, вес, хеши, профиль обработки, состояние.
- Привязки сохранённых файлов: ресурс, корневое TV, экземпляр галереи/путь вложения, файл.
- Временные привязки: пользователь, сессия редактора, галерея, файл, время активности.

Конкретные классы xPDO и схема миграций определяются разработкой. Рекурсивный обход поддерживает вложенные объекты и JSON-строки MIGX, имеет ограничение глубины/размера и распознаёт только валидный формат MultiPic. Не искать обычные строки URL по всей базе.

## 8. Сохранение, копирование и удаление

- Загрузки сразу видны, но сохранённая галерея меняется только после успешного сохранения ресурса.
- Вложенный MIGX передаёт изменения в родительскую форму, затем в ресурс. Отмена на любом уровне не изменяет сохранённое состояние.
- Изменения помечают форму ресурса как изменённую. Если загрузка ещё идёт, сохранение предупреждает/ожидает завершения; молчаливой потери файлов нет.
- До фиксации сверять версию редактируемого состояния: устаревшее окно не должно незаметно затереть свежие изменения.
- После успешной записи ресурса обновить привязки по фактически сохранённому JSON, сбросить затронутый кеш. Ошибка записи не запускает удаление файлов.
- Удаление карточки физически применяется после сохранения. При отсутствии сохранённых и временных привязок сразу удалить основной файл и превью, без корзины и семидневного хранения.
- Скрытый файл остаётся используемым. Прямой URL скрытого файла доступен; глазик не является защитой доступа.
- При копировании ресурса сохраняются поля, подписи, порядок, видимость; физические файлы общие. Удаление в копии не затрагивает оригинал.
- При удалении/дублировании строки или месяца во вложенном MIGX учёт пересчитывается по всему сохранённому дереву.
- Ресурс в корзине продолжает удерживать файлы. Окончательное удаление освобождает привязки и удаляет никем не используемые файлы.
- Произвольные ссылки в HTML/CSS/сторонних модулях не отслеживаются — пользователь согласовал эту границу.
- Временные файлы брошенной сессии очищаются через 24 часа без активности; активность продлевает срок. Сбой удаления фиксируется для повторной попытки и не изображается успешной очисткой.
- При повреждении JSON или невозможности полного пересчёта удаление блокируется для затронутых данных до восстановления учёта.
- При деинсталляции по умолчанию сохраняются файлы и данные. Полное уничтожение — отдельное явное действие, не часть обычного удаления пакета.

## 9. Вывод на сайте — проектный API

Сниппет не подключает автоматически слайдеры, стили и JS. Дизайн сайта определяется шаблонами. На фронтенде дополнительных размеров изображений компонент не создаёт.

| Параметр | Значение |
| --- | --- |
| tv | Имя TV для чтения |
| resource | ID источника, по умолчанию текущий ресурс |
| value | Готовое значение MultiPic из строки MIGX; приоритет над tv/resource |
| tpl | Чанк одного изображения |
| tplWrapper | Необязательная обёртка, содержимое в `[[+output]]` |
| limit | 0 — все; положительное число ограничивает вывод |
| offset | Пропуск после выбора чётности |
| parity | all, odd, even |
| toPlaceholder | Имя плейсхолдера для результата |
| output | html или array; массив используется через API Fenom/runSnippet, а не печатается как строка |

Пустой результат по умолчанию не выводит обёртку. Скрытые исключаются до нумерации. Порядок операций: active → индекс с 1 → parity → offset → limit. Это правило одинаково для всех способов вывода. В карточку передавать исходный индекс видимой галереи и индекс текущей выборки отдельно.

Обязательные данные элемента для вывода: file, url, width, height, title, alt, active; вычисляемые idx, odd/even, first/last с документированной семантикой. idx — позиция среди включённых до фильтра parity; first/last — в итоговой выборке.

Пример проектного вызова:

```modx
[[MultiPic?
    &tv=`constructionPhotos`
    &resource=`123`
    &tpl=`multipicItem`
    &tplWrapper=`multipicWrapper`
    &limit=`12`
    &parity=`odd`
]]
```

В чанке строки MIGX передаётся значение поля через value. Обычный foreach получает данные из версионированного JSON; приложение самостоятельно фильтрует active либо использует массив от сниппета. Финальные рабочие примеры Fenom и экранирования должны быть проверены на установке, не только написаны по памяти.

Кешируемый вызов поддерживается. При получении галереи другого ресурса определить и проверить стратегию инвалидирования зависимых страниц; кеш самого источника не гарантирует обновления страницы-потребителя. Подписи экранировать по контексту HTML/атрибута, данные редактора не исполнять как MODX-теги.

## 10. Безопасность и производительность

- Доступ только через авторизованные процессоры MODX с проверкой прав и защиты запросов менеджера.
- Проверка доступа к ресурсу, TV, контексту и источнику на сервере.
- Запрет выхода за корень источника, обхода через symlink, перезаписи чужих файлов и удаления произвольных путей.
- Лимиты файлов/пикселей/очереди, серверная защита от обхода клиентских ограничений.
- В админке используются готовые маленькие превью. Интерфейс подключается один раз на страницу и только при наличии поля; скрытые/неоткрытые редакторы по возможности инициализируются лениво.
- При множестве месяцев не загружать все полноразмерные фотографии и не создавать отдельный тяжёлый JS-пакет для каждой галереи.
- На фронтенде нет обработки изображений и запроса БД на каждую карточку; служебные запросы объединяются.
- Вспомогательная проверка целостности умеет показать отсутствующие файлы, восстановить привязки поддерживаемых TV и повторить неудачную очистку. Она не удаляет произвольные файлы источника.
