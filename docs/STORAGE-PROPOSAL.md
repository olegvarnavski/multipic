# Хранение MultiPic 0.2.0-alpha

Основные файлы: `<источник>/<папка TV>/<ID ресурса>/<SEO-имя>-<fileID>.<ext>`.
Все галереи одного ресурса при одинаковой настройке папки используют один каталог. Настройка папки TV и выбранный медиаисточник сохраняются.

До первого сохранения нового ресурса используется общий `_incoming/`. После получения ID файл копируется в папку ресурса, проверяется SHA-256, обновляются реестр и JSON. Старый адрес временно сохраняется для открытых редакторов; heartbeat обновляет адреса в форме.

При копировании ресурса физические фотографии остаются общими. Каталог означает владельца первой сохранённой загрузки, а не полный список мест использования. Он может остаться после удаления страницы, если фото нужно другой галерее. Порядок, название, ALT и видимость независимы. Выбранный в файловом браузере управляемый файл MultiPic переиспользуется без копирования и повторного сжатия. Обычный внешний файл из разрешённого источника копируется в хранилище MultiPic.

Дедупликация новых загрузок: SHA-256 исходника + медиаисточник + логическая папка TV + профиль обработки. ID ресурса не входит в ключ. Имя содержит случайный 128-битный ID, а не только порядковый номер.

Миниатюры: `{cache_path}multipic/thumbs/<ownerID>/<fileID>-240-v1.<ext>`. Эта папка может очищаться целиком. Миниатюры восстанавливаются при открытии поля; на сервере действует блокировка файла, в интерфейсе одновременно выполняются не более двух запросов. Выдача через POST-коннектор требует авторизации менеджера и доступа к файлу. Для сайта используйте `photo.url`; поле `thumb` служебное и в новых записях пустое. Основные фотографии в папках источника вручную не удаляйте.

## Перенос старых галерей

Установка обновляет схему таблиц, сохраняя настройки, чанки и файлы. Старые `files/xx/yy` продолжают работать. Массовый перенос при установке не запускается.

Сначала сохраните согласованную резервную копию БД и папок источников. Перенос меняет URL фотографий; прямые адреса вне TV/MIGX не отслеживаются. Закройте редакторы ресурсов на время переноса.

Предварительный отчёт без изменений:

```bash
php /path/site/core/components/multipic/cli/storage.php /path/site/config.core.php --plan --limit=100
```

Он показывает старый и новый путь, новый URL, доступность исходника и выбранный ресурс. Старый реестр не содержит исторического владельца: выбирается минимальный ID из зарегистрированных использований. Это техническое правило миграции.

Применение одной партии:

```bash
php /path/site/core/components/multipic/cli/storage.php /path/site/config.core.php --apply --limit=100
```

Повторяйте до сообщения «Перенесено файлов: 0». Лимит партии — от 1 до 500. Операции записываются в таблицу `multipic_moves` до копирования; повторный запуск сначала продолжает незавершённые операции. Существующий целевой файл с другой контрольной суммой не перезаписывается: операция останавливается для диагностики.

Каждый файл обновляется отдельной транзакцией: реестр и все найденные JSON TV, включая сериализованные вложенные MIGX. Метаданные и ID файлов не меняются. Повреждённый JSON останавливает операцию; ранее завершённые файлы остаются перенесёнными. После исправления причины повторите ту же команду. Автоматического обратного переноса нет; восстановление выполняется из согласованной резервной копии.

Старые копии удаляются штатной очисткой не ранее чем через 24 часа и только при отсутствии активных редакторов. Незавершённый журнал блокирует удаление основного файла. Пустые конечные каталоги удаляются по возможности. Регулярная очистка: `core/components/multipic/cleanup.php`; подробности в USAGE.md.

Ручное перемещение корня сайта или медиаисточника требует отдельной проверки абсолютных путей реестра. Не меняйте одновременно корень источника и структуру хранения.
