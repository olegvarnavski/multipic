# Статус 0.1.7-alpha

26.10.2026. MODX 2.x от 2.6, основной PHP 7.4; MODX 3 пока не поддерживается.

[Успешный прогон 40326834479](https://github.com/olegvarnavski/multipic/actions/runs/40326834479):

- MODX 2.6.0, 2.6.5, 2.8.5, 2.8.6: установка/обновление с 0.1.3, сохранение настроек/чанков/галереи/файлов, повторный resolver, удаление старой квоты пикселей.
- Переименованный каталог админки: HTTP-вход, TV, загрузка, сохранение/повторное открытие, раннее закрытие PHP-сессии.
- Отдельные PHP 8.2 unit: синтаксис, Gallery, Paths, xPDO API, GD, memory, snippet. Полный MODX на PHP 8.2 не сертифицирован.
- GD 6000×4061 JPEG при 192M; отсутствие квоты пикселей, расчёт памяти без переполнения, проверка формата/байтов, дедупликация, pending-очистка и удаление последнего использования.
- Пустые/повторно сериализованные значения MIGX, сохранение несовместимого содержимого, карточка отсутствующего файла.
- DOM: закрытие preview крестиком, справка только в МБ, очередь/формы, повторный файловый браузер, source URL, browser resize/retry и отказ cross-origin.

Артефакт dist взят из job MODX 2.8.5. Контрольная сумма — dist/SHA256SUMS.

Требует ручной приёмки: вложенные MIGX-окна, Ctrl/Shift в браузере файлов, телефон, Fenom и многопользовательские гонки. Очистка кандидатов ещё просматривает TV; кеш ресурсов сбрасывается консервативно. Перенос корня сайта требует проверки путей. Миниатюры пока находятся рядом с основными файлами и автоматически не восстанавливаются: при отсутствии thumb интерфейс подставляет основной файл. Смена структуры обсуждается отдельно — STORAGE-PROPOSAL.md. 0.1.7 её не меняет. Пустые каталоги могут оставаться после очистки файлов.
