# Статус 0.1.5-alpha

26.10.2026. Ветка MODX 2.x от 2.6, основной PHP 7.4. Сторонние дополнения для обычного TV не нужны. MODX 3 пока не поддерживается.

## Проверено

[Успешный прогон 40319474785](https://github.com/olegvarnavski/multipic/actions/runs/40319474785):

- MODX 2.6.0, 2.6.5, 2.8.5, 2.8.6; PHP 7.4.33, MySQL 5.7.
- Установка 0.1.3 с галереей/файлами, обновление до 0.1.5, сохранность пользовательской настройки/чанка/JSON/фото. Повторное создание схемы не удаляет данные.
- Загрузка, дедупликация, запрет формата источника, подмены URL и размеров; копирование ресурса и удаление последнего использования.
- Проверка целостности и очистка просроченной операции pending.
- Рендер TV и настроек, исходный inputTVid с синтетическим MIGX ID, карточка отсутствующего файла.
- HTTP: вход, TV на странице ресурса, multipart-загрузка, сохранение и повторное открытие; раннее закрытие PHP-сессии не теряет токен редактора.
- Отдельный job PHP 8.2: синтаксис и standalone Gallery/Paths/GD/snippet/xPDO API. Это не подтверждение всего MODX на PHP 8.2.
- DOM-симуляция: порядок очереди, несколько полей, подписи/скрытие, блокировка сохранения при загрузке, несколько выбранных файлов сервера, место вставки при сортировке.

Установщик dist взят из задания MODX 2.8.5. Контрольная сумма — dist/SHA256SUMS.

## Исправления 0.1.5 — проверено

- Реальная обработка GD обычного JPEG 6000×4000 при memory_limit=192M, оценка пиков и отдельного EXIF-буфера на PHP 7.4 и standalone PHP 8.2.
- Пустые значения MIGX [], {}, null, пустая строка и повторная сериализация: установленный TV-рендер. Несовместимое непустое содержимое сохраняется без изменений.
- Браузерная подготовка: геометрия/качество/формат, очистка canvas и URL, повтор после отказа PHP. Эти проверки выполнены в Node/DOM со вспомогательными объектами, а не в живом Chrome.
- Импорт серверного файла: повтор через доступный same-origin URL, запрет запроса на сторонний origin. Исходники не меняются.

Это не подтверждает, что конкретное поле gallery пользователя было пустым: значение строки не предоставлено. При непустом старом формате автоматической миграции нет.

## Требует ручной приёмки

Настоящие окна MIGX и вложенного MIGX; отмена и копирование строк; ограниченные ACL; Ctrl/Shift в штатном файловом браузере; телефон; Fenom и сложные подписи; конкуренция нескольких PHP workers. DOM и HTTP обычного TV не заменяют эту приёмку.

## Оставшиеся ограничения

- При очистке кандидатов сохраняется просмотр TV для защиты ссылок. Партия ограничена 100 файлами; полной перестройки refs больше нет.
- Сброс кеша ресурсов общий, зависимости межресурсного вывода ещё не индексируются.
- Все изображения перекодируются GD. Дополнительная дедупликация готовых байтов не реализована.
- Перенос корня сайта/URL требует согласованной правки реестра и JSON. --check показывает проблемы; опасные пути не удаляются.
- Журнал pending защищает новые операции. Старые незарегистрированные файлы автоматически не инвентаризируются.
- Отдельного визуального интерфейса обслуживания пока нет; доступна CLI-проверка.
- Анимация, HEIC/GIF/SVG, удалённые источники, MIGXdb и MODX 3 вне выпуска.
- Имя галереи из произвольного поля месяца MIGX пока не сопоставляется.
