# MultiPic — документация 0.1.6-alpha

Статус: описывает текущий код alpha. Примеры интеграции MODX/MIGX/Fenom требуют проверки на реальной установке. Полная документация будет завершена вместе с прохождением матрицы совместимости.

## TV и MIGX

У TV доступны «Максимум изображений» (`maxFiles`), «Папка в медиаисточнике» (`folder`) и «Источник файлов» (`mediaSource`) — выпадающий список существующих источников. Выбранный здесь источник используется во всех контекстах и внутри MIGX. Значение «Нет» (0) сохраняет штатный выбор источника на вкладке «Источники файлов» по контексту ресурса. Поддерживаются локальные файловые источники. Создайте TV `photosInput` типа multipic. Для использования только внутри MIGX назначать его шаблону не требуется.

Фрагмент конфигурации формы MIGX:

```json
[{"caption":"Месяц","fields":[
  {"field":"title","caption":"Месяц"},
  {"field":"photos","caption":"Фотографии","inputTV":"photosInput"}
]}]
```

Во вложенном MIGX такой же `inputTV` задаётся в конфигурации вложенной формы. Значение галереи — JSON-объект MultiPic, а не список URL. Сохранение вложенной формы передаёт его родителю; затем сохраняется ресурс.

Системные настройки пространства `multipic` снабжены русскими названиями и пояснениями: размер исходного файла задаётся в байтах, размеры изображения — в пикселях, качество JPEG/WebP — от 1 до 100.

## Обновление с предыдущих alpha

Установите новый пакет через управление пакетами без удаления предыдущей версии. После установки обновите страницу менеджера с Ctrl+F5 и откройте ресурс заново. Уже открытые формы старой версии используют прежние токены. Новая служебная таблица `multipic_editors` создаётся установщиком; файлы галерей сохраняются.

## Редактор

Можно выбирать несколько файлов с компьютера, перетаскивать файлы в поле, добавлять из файлового браузера. В штатном файловом браузере несколько файлов выбираются с Ctrl/⌘ или Shift, затем добавляются одной группой. Нужна ручная приёмка на вашей версии менеджера. Исходник на сервере не удаляется.

Порядок новых загрузок — естественная сортировка имён. Новые добавляются в конец. Перетаскивание за маркер меняет порядок. Глазик выключает вывод, но не закрывает прямую ссылку. Карандаш раскрывает название и ALT; оба необязательны. После изменения требуется сохранить все родительские формы MIGX и ресурс.

При загрузке одного ошибочного файла остальные продолжаются. У ошибки есть «Повторить». При превышении лимита оставшиеся имена показываются под полем. При незавершённой загрузке установлены проверки beforeSubmit формы ресурса и doSubmit окна MIGX. Поведение кнопок и клавиатуры должно быть подтверждено на вашей версии MIGX.

## Сниппет

```modx
[[MultiPic? &tv=`gallery` &tpl=`multipicItem` &tplWrapper=`multipicWrapper`]]
[[MultiPic? &tv=`gallery` &resource=`123` &limit=`1`]]
[[MultiPic? &tv=`gallery` &parity=`odd` &limit=`6`]]
[[MultiPic? &tv=`gallery` &parity=`even` &limit=`6`]]
```

Из строки MIGX:

```modx
[[MultiPic? &value=`[[+photos]]` &tpl=`multipicItem`]]
```

Для произвольных подписей/сложного JSON надёжнее передавать value программно в Fenom; вложение JSON в текст MODX-тега требует отдельной проверки экранирования на конкретном парсере.

Параметры:

| Имя | По умолчанию | Значение |
| --- | --- | --- |
| tv | пусто | Имя TV |
| resource | текущий | ID ресурса-источника |
| value | не задано | Готовое значение галереи; приоритет над tv/resource |
| tpl | multipicItem | Чанк фото или @FILE |
| tplWrapper | пусто | Обёртка с output и count |
| parity | all | all, odd, even |
| offset | 0 | Пропуск после выбора чётности |
| limit | 0 | 0 — все |
| output | html | array возвращает PHP-массив для программного вызова |
| toPlaceholder | пусто | Имя плейсхолдера HTML-результата |

Скрытые исключаются, оставшимся присваивается idx с 1, затем parity, offset, limit. first/last относятся к итоговой выборке; iteration — номер в ней. Пустая галерея не выводит обёртку.

Плейсхолдеры картинки: url, width, height, title, alt, file, idx, iteration, first, last, odd, even. Сниппет экранирует url/title/alt для HTML и предотвращает интерпретацию квадратных скобок как MODX-тегов. В режиме array данные сырые: шаблон обязан экранировать текст.

## Чанки

Обычный чанк — по имени. Статический чанк MODX — также по имени, файл читает сам MODX. Файл напрямую:

```modx
[[MultiPic? &tv=`gallery` &tpl=`@FILE gallery/item.tpl`]]
```

Путь относителен `multipic.chunks_path`; чтение вне базовой папки запрещено. Такие файлы обрабатываются стандартным парсером чанков MODX, не автоматически Fenom. Демонстрационные чанки устанавливаются только в категорию MultiPic, файловых копий примеров нет.

## Fenom

Требуется настроенный Fenom/pdoTools.

```smarty
{set $photos = $_modx->runSnippet('MultiPic', ['tv'=>'gallery', 'output'=>'array'])}
{foreach $photos as $photo}
  <img src="{$photo.url | escape}" alt="{$photo.alt | escape}" loading="lazy">
{/foreach}
```

Прямое чтение:

```smarty
{set $gallery = $_modx->resource.gallery | fromJSON}
{foreach $gallery.items as $photo}
  {if $photo.active}
    <img src="{$photo.url | escape}" alt="{$photo.alt | escape}">
  {/if}
{/foreach}
```

## Настройки и обработка

`multipic.folder=multipic/`, `max_files=30`, `max_edge=2560`, `quality=95`, `max_bytes=20971520` (20 MiB), `max_pixels=32000000` (32 MP). Реальные лимиты PHP могут быть ниже. Исходные большие фото уменьшаются; маленькие не увеличиваются. В текущей alpha все принятые изображения повторно кодируются GD для удаления метаданных — даже небольшие. Отдельный исходник не хранится. PNG сохраняет прозрачность. JPG/WebP — качество 95. Анимация не поддерживается.

## Хранение и копирование

Основные файлы — folder/files/xx/yy/, превью — folder/thumbs/xx/yy/. Профиль превью — до 240 px, качество JPG/WebP не выше 85; основные файлы сохраняются с качеством 95. Имя содержит нормализованное название и случайный 128-битный суффикс. Дедупликация: исходный SHA-256 + источник/папка + профиль обработки. Сверка готовых байтов пока не реализована.

При копировании ресурса галереи ссылаются на те же файлы. Порядок/подписи/видимость находятся в JSON каждой галереи. Проверка копирования и вложенного MIGX входит в обязательную приёмку.

## Удаление и очистка

Карточка удаляется из формы сразу, физическое удаление — после сохранения, если нет refs и временных leases. Данные в корзине MODX удерживают файлы. Временные привязки от брошенных сессий действуют 24 часа; heartbeat открытого поля продлевает их. Прямые URL в HTML/CSS не учитываются.

Команда ручной очистки (подставьте реальные пути и PHP):

```bash
/usr/bin/php /home/user/site/core/components/multipic/cleanup.php /home/user/site/config.core.php
```

Пример cron раз в час:

```cron
0 * * * * /usr/bin/php /home/user/site/core/components/multipic/cleanup.php /home/user/site/config.core.php
```

При смене папки старые пути остаются действующими. Резервная копия включает БД и все папки источников. Пакет при деинсталляции не удаляет фотографии и таблицы автоматически.

## Кеш

Для корректности вывода с другого ресурса alpha очищает кеш всех ресурсов после сохранения. Это консервативное временное решение; адресная инвалидизация зависимостей запланирована до стабильного выпуска.

## Диагностика

- Загрузка не начинается: сессия mgr, права save_document/new_document и доступ к TV/источнику.
- Файл не получен: upload_max_filesize, post_max_size и ограничения веб-сервера.
- Формат не поддержан: PHP GD с JPEG/PNG/WebP; EXIF для ориентации JPEG.
- Не создаётся папка: права записи и отсутствие символических ссылок в пути.
- Пропавшее изображение: не удаляйте вручную файлы хранилища; восстановите из согласованной копии БД/файлов.
- Ошибки сервиса записываются в журнал MODX с префиксом [MultiPic].


## Структура JSON и интеграция

Версия формата 1: объект `type=multipic`, `version=1`, `gallery`, `tv`, `session`, `items`. `items` — упорядоченный список. В каждом элементе `id`, `file`, `url`, `thumb`, `width`, `height`, `title`, `alt`, `active`. Порядок списка определяет сортировку. `session` — служебная привязка редактора, не токен авторизации: без активной сессии менеджера и MODAUTH она не разрешает загрузку. Не редактируйте служебные поля вручную.

Таблицы с префиксом сайта: `multipic_pending` — журнал незавершённых загрузок; `multipic_schema` — версия схемы; `multipic_editors` — открытые редакторы; `multipic_files` — физические файлы; `multipic_refs` — сохранённые ссылки resource/TV/file; `multipic_leases` — временные привязки редакторов. Скрытые фото сохраняют ссылки. При повреждении данных очистка останавливается и пишет причину в журнал.

Штатные события: OnTVInputRenderList, OnTVInputPropertiesList, OnDocFormPrerender, OnBeforeDocFormSave, OnDocFormSave, OnResourceDuplicate, OnResourceDelete, OnEmptyTrash. Собственные публичные события пока не объявлены.

Файловый чанк задаётся относительно `multipic.chunks_path` (по умолчанию `{core_path}elements/chunks/`). Статический чанк MODX можно хранить в любой разрешённой настройками MODX папке и вызывать по имени. Прямой @FILE обрабатывается стандартным парсером MODX; Fenom автоматически в нём не включается.

## Обновление и резервные копии

Перед обновлением сохраняйте БД и все используемые папки медиаисточников. После загрузки новой версии transport.zip установите её через менеджер пакетов и очистите кеш. Пользовательские значения системных настроек и демонстрационные чанки не перезаписываются. При деинсталляции физические фото и служебные таблицы остаются; удаление данных вручную — отдельная операция владельца сайта. После деинсталляции не ожидайте работоспособности собственного типа TV до повторной установки.

Перенос сайта требует согласованного восстановления БД и файлов. Реестр alpha содержит абсолютные пути, поэтому смена абсолютного корня сайта требует отдельного переноса путей реестра; автоматическая миграция не реализована. Не запускайте очистку после такого переезда до корректировки и проверки путей. Если меняется только домен, абсолютные URL медиаисточника также требуют проверки.

## Сессия открытой галереи

Токены редакторов хранятся отдельными строками в служебной таблице `multipic_editors`, привязаны к пользователю и токену его входа в менеджер. Они не зависят от последующей записи PHP-сессии. Срок бездействия — 24 часа; запросы загрузки и heartbeat продлевают его. Просроченные записи удаляются вместе с плановой очисткой. Проверки входа, доступа к ресурсу, TV и источнику сохраняются. Если вход в менеджер действительно истёк, войдите снова и откройте ресурс заново.

## Надёжность 0.1.6

Установщик добавляет pending/schema и недостающий индекс leases.touched. Повторный запуск сохраняет существующие данные, значения настроек и пользовательские чанки. Штатная загрузка требует права file_upload и разрешённого формата в источнике, а также прежних прав на ресурс/TV/источник.

Основной файл, которого нет на диске, отмечается в карточке. Его можно сохранить в существующей галерее для последующего восстановления или удалить карточку; файл, которого нет даже в реестре, требуется удалить из галереи перед сохранением. Отсутствующее превью заменяется основным изображением только в интерфейсе.

Обработка изображений идёт вне общей блокировки. Перед регистрацией повторно проверяется дедупликация. Журнал фиксирует пути до записи файлов, чтобы уборка могла завершить просроченную операцию после аварийного завершения PHP. Он не обнаруживает автоматически бесхозные файлы, оставшиеся до 0.1.6.

Очистка обрабатывает до 100 записей за запуск. Для безопасности перед удалением кандидатов остаётся просмотр TV; на очень больших базах его дальнейшая оптимизация запланирована. Просроченный pending удаляется только при отсутствии активного редактора. Если путь не принадлежит известному локальному источнику или содержит символическую ссылку, удаление блокируется и записывается причина.

Проверка целостности без удаления и правки реестра (первые 1000 записей):

```bash
/usr/bin/php7.4 /home/user/site/core/components/multipic/cleanup.php /home/user/site/config.core.php --check
```

Для следующей страницы передайте выданный next_after после --check. Код возврата 2 означает найденные проблемы; 1 — ошибка выполнения. Обычная очистка также возвращает 2 при неудачных удалениях. Команду переноса путей автоматически эта версия не выполняет: после переезда сначала проверяйте хранилище. Общий кеш ресурсов пока сбрасывается консервативно.

При ошибке загрузки сообщите код запроса из карточки: по нему находится запись [MultiPic connector] в журнале MODX. Токены и тело запроса не журналируются.

## Большие фотографии и значения MIGX (0.1.6)

Размер файла в МБ не равен памяти декодированного изображения: 6000×4000 — это 24 Мп. Сервер оценивает пик последовательных операций GD, освобождает исходник перед превью и отдельно резервирует память для EXIF-поворота. Проверено обычное JPEG 6000×4000 при memory_limit=192M; это не гарантия обработки любого формата/ориентации при таком лимите.

Если сервер сообщает отказ по памяти или числу пикселей, браузер пытается уменьшить фото до настроенного max_edge, сохраняя пропорции, формат и прозрачность PNG, и один раз повторяет загрузку. Для JPEG/WebP применяется настроенное качество. Это дополнительное перекодирование; SHA-256 для дедупликации считается по реально отправленным байтам, поэтому браузерная и серверная обработка одного оригинала могут дать разные записи. Исходный файл на компьютере/сервере не перезаписывается. Если max_edge=0, автоматическое уменьшение отключено.

Для выбора с сервера браузерная подготовка возможна только при доступном URL того же origin (без отправки авторизации на сторонние домены). Если URL недоступен, остаётся серверная обработка: потребуется меньший оригинал или достаточный лимит памяти PHP. Защита от нехватки памяти не отключается.

В MIGX используйте имя созданного TV в inputTV, например multipic. Пустые значения [], {}, null и повторная JSON-сериализация поддержаны. Непустые массивы старой галереи не являются MultiPic: используйте отдельное имя поля, например photos, или перенесите прежние данные. Рендер ошибки сохраняет исходное скрытое значение; старые данные автоматически не удаляются.

## Лимиты, файловый браузер и пути (0.1.6)

Стандартный лимит — 20 МБ и 32 Мп (32000000 пикселей, ширина × высота). Фото 6000×4061 — 24,366 Мп, оно укладывается. При обновлении прежнее стандартное значение 24 Мп автоматически поднимается до 32 Мп. Другие вручную заданные значения не перезаписываются.

Справка под галереей показывает значения именно этой установки. Если PHP ограничивает загрузку с компьютера сильнее, этот предел выводится отдельно. Для post_max_size оставлен запас 64 КБ под служебные поля формы. Размер после уменьшения в справке не отображается.

Для отказа по памяти, размеру файла или числу пикселей выводится «Файл слишком большого размера. Выберите другой.». Техническая причина и код запроса остаются в журнале; автоматический повтор после уменьшения сохраняется для памяти/пикселей.

Файловый браузер поля переиспользуется при повторном открытии и не зависит от наличия ранее созданного браузера MODX. Кнопка не предполагает конкретного адреса админки. URL оригинала строится от настроенного URL источника, а не относительно страницы менеджера.

MultiPic в обычном TV и внутри MIGX хранит в photo.url готовый веб-адрес с URL источника, например /uploads/multipic/files/ab/cd/photo-ID.jpg. Это URL от корня сайта, а не путь файловой системы /home/.... Добавлять $userfile=/uploads/ к нему не нужно.

Пример внутри foreach строк MIGX, где $child.gallery — MultiPic:

```smarty
{set $photos = $_modx->runSnippet('MultiPic', ['value'=>$child.gallery, 'output'=>'array'])}
{foreach $photos as $photo}
    {set $img_child = 'phpthumbon' | snippet : [
        'input'=>$photo.url,
        'options'=>'w=1600&q=90'
    ]}
    <img src="{$img_child | escape}" alt="{$photo.alt | escape}" loading="lazy">
{/foreach}
```

phpThumbOn нужен только для этого необязательного примера. Без дополнительной обработки используйте src={$photo.url | escape}. Аналогичный пример устанавливается в категории MultiPic как multipicExampleMigx. Поле img с другим inputTV, например mixedImage/imgMigx, может иметь другой договорённый формат: его старую логику префикса не нужно менять автоматически.
